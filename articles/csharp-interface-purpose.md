## インターフェースとは

### エアコンを例にインターフェースのイメージを掴む

インターフェース（interface）を文字通り訳すと「境界面」です。エアコンを操作するとき、私たちはエアコン内部の仕組みを何も知りません。ユーザーがエアコンを操作するときに触れるのは、リモコンやスマホアプリのボタンだけです。この**ユーザーが触れる部分**、つまりユーザーとエアコンの境界面にあたるものがインターフェースです。もしインターフェースがなければ、極端な話、ユーザーはエアコン内部の仕組みを理解したうえで直接操作しなければなりません。インターフェースがあるおかげで、**ユーザーはインターフェースだけを意識すればよく、その奥にある複雑な仕組みを知る必要がありません。**

### ソフトウェア開発におけるインターフェース

ソフトウェア開発にも同じように**機能を利用する側が触れる部分と、内部の実装とを切り離す考え方**があります。それを言語の機能として用意したものが、C# や Java の `interface` です。

C# や Java のインターフェースの実態は、**メソッドやプロパティの宣言だけを並べた型**です。

コードで見てみます。

```cs
// インターフェース：メソッドやプロパティを並べ、「何ができるか」を宣言する
public interface INotifier
{
    void Send(string message);
}

// 具象クラス：インターフェースの規約に従い、処理を実装する
public class EmailNotifier : INotifier
{
    public void Send(string message)
    {
        // 宛先を組み立て、SMTPサーバーに接続し、本文を整形して送信する…
        // といったメール送信に関する実装詳細がここに入る
    }
}

// 具象クラスは複数あってよい。同じ宣言に対して、実装の中身はそれぞれ違う
public class SmsNotifier : INotifier
{
    public void Send(string message)
    {
        // 電話番号を取得し、文字数制限に収まるよう本文を切り詰めて送信する…
        // といったSMS送信に関する実装詳細がここに入る
    }
}

// 通知機能を利用する側：触れるのはインターフェースだけ。具象クラスは一切出てこない
public void NotifyCompletion(INotifier notifier)
{
    notifier.Send("処理が完了しました");
}
```

`INotifier` というインターフェースが宣言しているのは「メッセージを送信する（`Send()`）」という実現したい振る舞いだけです。その中身にあたる処理の詳細は書かれていません。実際に**どうやって**送信するかに関する記述は、`INotifier` を実装した `EmailNotifier` や `SmsNotifier` 側にあります。`INotifier` を実装する以上、どちらも インターフェースの規約に従い、`Send()` を必ず用意しなければなりません。

利用する側から見れば、インターフェースは**メニューのようなもの**です。そこに並んでいるのは「何ができるか」だけで、どうやって実現するかは書かれていません。

そしてエアコン本体を直接触らず、リモコンを通じて操作するのと同じように、**利用する側は具象クラスに直接アクセスせず、インターフェースにアクセスします**。上のコードでも、`NotifyCompletion` は `INotifier` 経由で `Send()` を呼ぶだけで、`EmailNotifier` と `SmsNotifier` には一度も触れていません。
